# Discovery final engineering hardening — 2026-09-24

## Software readiness boundary

Automatic Discovery remains one evidence path: exact topology and interface
binding, quarantine, corpus recognition, safe inference, experiment authority,
verification/rollback, EvidenceGraph persistence, and compact recipe reuse.
Corpus, community, family, inferred grammar, and compiled recipe states are not
write authority. When safe automatic evidence is exhausted, the canonical TUI
shows one Lab action; captured evidence returns to the same graph and pipeline.

Compact recipes are bounded, deterministic, generation- and evidence-revision
aware, atomically replaced, and rejected on corruption, symlinks, schema/field
mismatch, identity/descriptor/firmware/generation changes, or invalid evidence.
Inference and corpus inputs have explicit record and byte budgets.

## Physical acceptance plan — not yet executed

Use the installed candidate built from the reviewed commit and record exact
device identity, firmware, connection mode, package hash, and service logs.

### Known-answer G305

1. Cold start and confirm the native HID++ fast path, one HID reader, normal
   remapping, current DPI, polling, battery, and notifications.
2. Change DPI through the existing proven software path; verify canonical
   readback and physical sensitivity, then restore the baseline.
3. Change polling only through the established path; verify protocol readback
   and an independent motion-timing measurement, then restore the baseline.
4. Exercise physical DPI cycling, receiver removal/reinsert, late receiver,
   mouse power cycle, service restart, and ten rapid transitions. Confirm event
   order, no duplicate notifications, no stuck input, and prompt remapping.
5. Restart with the persisted exact identity and measure the known-device warm
   path. Change one identity dimension in a fixture only and confirm invalidation.

### Independent native Razer control

Repeat identity binding, read/write/readback/restore where already supported,
reconnect, remapping, and fast-path checks on one exact supported Razer model.
Do not generalize the result to other Razer identities.

### Unknown-family control

On one genuinely different mouse, verify observation-first quarantine,
non-authorizing corpus recognition, precise refusal reasons, and one Lab action.
No write is permitted until the normal exact-model proof path independently
qualifies it.

Physical results must be recorded separately; this plan is not validation.
